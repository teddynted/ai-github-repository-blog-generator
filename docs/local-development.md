# Local Development

This guide explains how to run and develop the **GitHub AI Blog Generator** on your machine. There is **no local model**: content is generated by Claude, either through your **Claude Code subscription** (default, no API key) or the **Anthropic API** / **Amazon Bedrock** — the same generators production runs. The orchestration plane (n8n + PostgreSQL + Redis) runs locally in Docker Compose.

Related: [Deployment](./deployment.md) · [Workflows](./workflows.md) · [AI Provider Router](./hybrid-ai-routing.md) · [Contributing](./contributing.md).

## 2. Local content generation (the fast loop)

The primary local workflow is iterating on content with **`cmd/content`**, which
reuses the exact production pipeline (`internal/contentsuite` + the same
generators). No AWS, no Compose, no model server.

```bash
# Generate the blog from a fixture using your Claude Code subscription (no API key)
make blog-local
# …or any artifact/provider:
go run ./cmd/content --artifact architecture --provider anthropic --context fixtures/v0.3.0.json --output output/

# Preview the exact prompt without calling a provider or spending tokens
go run ./cmd/content --artifact blog --provider claude-code --context fixtures/v0.3.0.json --dry-run
```

Providers: `claude-code` (default, subscription), `anthropic` (`ANTHROPIC_API_KEY`), `bedrock` (AWS creds). `--hybrid` routes the whole suite through the local AI Provider Router. See the README's [Local Content Development](../README.md#local-content-development--prompt-testing).

## 3. Docker Compose (orchestration plane)

The `instance/` directory contains the same Compose stack that runs on the EC2
host — **n8n + PostgreSQL + Redis** — so local and production topology match. You
only need this to work on the n8n publishing/approval workflows.

```bash
cp .env.example .env      # fill in values (see Section 4)
docker compose -f instance/docker-compose.yml up -d
docker compose -f instance/docker-compose.yml logs -f n8n
```

- **n8n** → http://localhost:5678
- **PostgreSQL** and **Redis** back n8n; they are not exposed.

Stop with `docker compose -f instance/docker-compose.yml down` (add `-v` to remove volumes). There is no model server to run.

## 4. Environment Configuration

Local configuration lives in `.env` (git-ignored). Start from `.env.example`:

| Variable | Description | Example |
| --- | --- | --- |
| `AWS_REGION` | Region for AWS/Bedrock testing | `us-east-1` |
| `AWS_PROFILE` | Local credentials profile | `blog-dev` |
| `ANTHROPIC_API_KEY` | For `--provider anthropic` (Provider Router fallback leg) | `sk-ant-…` |
| `BEDROCK_MODEL_ID` | For `--provider bedrock` / worker testing | `us.anthropic.claude-opus-4-8` |
| `N8N_ENCRYPTION_KEY` | n8n credential encryption key | random 32+ chars |
| `POSTGRES_PASSWORD` | Local n8n metadata DB password | random |
| `QUEUE_URL` | Dev SQS queue URL (optional) | `https://sqs…/blog-gen-dev-events` |
| `PUBLISH_TRIGGER` | Optional trigger pattern (metadata) | `blog:` |
| `GITHUB_TOKEN` | Optional; for cloning private test repos | `github_pat_xxx` |

> Secrets in `.env` are for **local dev only**. In AWS, the Anthropic key and PATs live in Secrets Manager — see [Security](./security.md).

## 5. Building & Testing

The code is a **single Go module** (monorepo): shared logic lives under
`internal/`; each Lambda is an entry point under `lambdas/<fn>/`
(`registration`, `manual-trigger`, `release-context`, `scheduled-start`,
`scheduled-stop`, `idle-stop`), and the SQS-draining generator is `cmd/worker`.

```bash
make check          # gofmt check + go vet + go test -race -cover
```

Build deployable artifacts (Linux, **arm64** — the t4g host + Lambdas are Graviton):

```bash
make build          # → dist/<fn>/bootstrap and the worker binary
```

## 6. Running End-to-End Locally

1. **Content only (fast):** iterate with `cmd/content` (§2) — this exercises the
   full generator suite with no AWS.
2. **Orchestration:** start the Compose stack (§3), import the workflow JSON from
   `workflows/` ([Workflows → Importing](./workflows.md#11-importing-workflows)),
   and configure n8n credentials (SQS/AWS, GitHub) in the editor.
3. **Worker path:** with a dev SQS queue, enqueue a job envelope
   (`{"detail": {"repo_full_name": "...", ...}}`) and run `cmd/worker` locally
   (set `QUEUE_URL`, `BEDROCK_MODEL_ID`/`ANTHROPIC_API_KEY_SECRET`); watch it
   clone → analyze → generate (Bedrock → Anthropic) → skip-if-in-S3 → review → publish.

Iterate directly in the n8n editor; export changes back to `workflows/` and commit them.

## 7. Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `cmd/content` errors on `--provider claude-code` | Claude Code not installed / not logged in | Install Claude Code; run `claude` once to authenticate |
| `cmd/content` errors on `--provider anthropic` | `ANTHROPIC_API_KEY` unset | `export ANTHROPIC_API_KEY=sk-ant-…` |
| `AccessDeniedException` on `--provider bedrock` | Bedrock model access not enabled | Enable the Claude model in the Bedrock console (Model access) |
| n8n editor unreachable | Container not up / port clash | `docker compose ps`; check port `5678`; view logs |
| n8n loses credentials on restart | `N8N_ENCRYPTION_KEY` changed | Keep the key stable; persist the volumes |
| Go build fails for Lambda/worker | Wrong target arch | Set `GOOS=linux GOARCH=arm64 CGO_ENABLED=0` |
| `NoCredentialProviders` (SQS/Bedrock) | AWS creds not loaded | `aws sts get-caller-identity`; set `AWS_PROFILE` |
| Stack stuck `UPDATE_IN_PROGRESS` / rollback | Interrupted or failed deploy | Inspect `aws cloudformation describe-stack-events`; wait for auto-rollback |

If you're stuck, open an issue with logs and reproduction steps — see [Contributing → Issue Reporting](./contributing.md#8-issue-reporting).
