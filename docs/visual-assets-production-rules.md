# Visual Assets Production Rules

Provider-neutral production rules for the release visual-asset pack
(`output/releases/<version>/visual-assets.md`, generated by
`internal/visualassets`). These rules are the contract a generated prompt pack
must satisfy before it is considered production-ready for automated
image generation across **GPT Image, Claude-integrated workflows, Flux,
Midjourney, Stable Diffusion XL, and Nova Canvas**.

The generator already emits per-asset **Shared Render Constraints**, **Quality
Checklists**, **Render Guidance**, **Platform Optimization**, **Automation
Metadata**, and a **Final Validation Matrix**. This document consolidates the
cross-asset rules those sections reference, defines the canonical metadata
schema, and specifies the CI-checkable validation gates.

The four **canonical conceptual roles** every architecture visual depicts:

1. **Identity & Access**
2. **Event Routing & Scheduling**
3. **Serverless Orchestration**
4. **Elastic Compute & Observability**

These names and their visual roles must be identical across all assets. No
synonyms (no "security shield", "scheduler cluster", "orchestration core",
"metrics lens").

---

## 1. Global Hard Layout Constraints

Apply to every asset unless a platform rule overrides:

- Exactly **one** dominant focal cluster per frame.
- At most **four** major component groups (the canonical roles); no fifth group.
- A **reserved, empty text-safe zone** — nothing in the composition may intrude
  into it (headline zone and/or lower-third per the asset's placeholders).
- **No literal text, letters, numbers, logos, watermarks, or signatures** —
  ever. Copy is added later in compositing.
- Brand palette only: deep navy `#0B1F33` / `#12263A` background, `#FF9900`
  (amber) and `#4F9DFF` (blue) accents.
- Flat vector with **subtle** isometric depth; layered flat planes with soft
  drop shadows for hierarchy. No photorealism, no 3D render, no gradients beyond
  the dark background.

## 2. Global Rendering Priorities

Ordered — earlier rules win when two guidelines conflict:

1. **Silhouette readability** of the focal cluster (must survive down to 120px).
2. **Text-safe-zone integrity** (never encroached).
3. **Role clarity** — the four modules are individually recognizable.
4. **Brand consistency** (palette, flat-vector style).
5. Decorative detail (grid/circuit texture, rim light) — lowest priority; drop
   first if the frame gets busy.

## 3. Global Connector Rules

- Connectors between modules must **not cross** (target: zero visible
  crossings).
- One consistent **directional arrow hierarchy** (primary flow bolder than
  secondary).
- No connector may overlap or point into a reserved text-safe zone.
- On mobile/vertical assets, **omit fine connector detail** that disappears at
  small sizes — imply flow with spacing and a single bold arrow instead.

## 4. Global Mobile-Safe Rules

For social/video assets (YouTube, X, LinkedIn, TikTok, Shorts):

- Large simple shapes; high-contrast focal region.
- Strong foreground/background separation.
- **Vertical assets (Shorts, TikTok):** keep the **center 40% vertical band**
  clear of platform UI overlays; keep important detail off the **right-edge
  interaction rail**; reduce architectural complexity vs. desktop assets.
- **LinkedIn banner:** keep detail out of the top-left profile-photo overlap;
  respect desktop and mobile banner safe zones.
- **GitHub social card:** legible in dark-mode preview and in Slack / Discord /
  X link unfurls; strong center-right focal cluster.

## 5. Standardized Metadata Schema

Every asset carries one automation metadata block with this exact schema and
field order:

```yaml
asset_id:        # stable snake_case id, e.g. youtube_thumbnail
version:         # release tag, e.g. v0.6.0
theme:           # event_driven_architecture
platform:        # YouTube | GitHub | LinkedIn | X | Blog | Docs | TikTok | ...
aspect_ratio:    # e.g. 16:9, 9:16, 1:1
render_priority: # high | medium | low
primary_use:     # video | social | docs | repository
supports_motion: # true | false (true only for the animated assets)
safe_text_zones: # list, e.g. [headline, lower_third]
```

**Currently emitted by the generator:** `asset_id`, `version`, `theme`,
`render_priority`, `primary_use`, `supports_motion`. **To fold in** (already
present elsewhere in each asset section — the header line and text placeholders):
`platform`, `aspect_ratio`, `safe_text_zones`. Standardizing these into the YAML
block is a small, low-maintenance generator change (see `automationMeta`).

## 6. Production Validation Gates

Machine-checkable gates. An asset **fails** the gate if any rule is violated;
the pack ships only when every asset passes.

```yaml
production_validation_gates:
  max_connector_crossings: 0
  min_negative_space_ratio: 0.35
  min_focal_contrast: high
  max_major_component_count: 4
  reserved_text_zone_overlap: forbidden
  mobile_preview_legibility: required
  literal_text_in_image: forbidden
  palette_out_of_brand: forbidden
  invented_aws_services: forbidden
```

Checklist form (for a human or CI reviewer, per asset):

- [ ] Zero visible connector crossings
- [ ] Negative space ≥ 35% of the frame
- [ ] Focal object contrast reads as high against the background
- [ ] No more than four major component groups
- [ ] No element overlaps a reserved text zone
- [ ] Focal cluster legible at 120px (mobile preview)
- [ ] No literal text/logos rendered
- [ ] Palette within brand (navy / amber / blue only)
- [ ] No AWS services beyond those in the Release Context

These map to the generator's existing per-asset **Quality Checklist** and the
**Final Validation Matrix**; this section is the CI-enforceable superset.

## 7. Claude Image Generation Policy

Rules for any future Claude (or agent) generating or refining these images:

- **Never invent AWS services**, components, numbers, or file names not present
  in the source specification / Release Context.
- **Never add text** of any kind to an image — leave text-safe zones empty for
  compositing.
- **Preserve the brand palette** exactly (navy `#0B1F33`/`#12263A`, amber
  `#FF9900`, blue `#4F9DFF`); no other hues.
- **Preserve reserved text-safe zones**; nothing may intrude into them.
- **Prefer simplified geometry** over decorative detail; drop ornamentation
  before dropping clarity.
- **Prioritize silhouette readability on mobile** — assume a 120px preview.
- **Keep diagrams label-safe**: component interiors stay empty so labels can be
  added later; nodes evenly spaced, connectors non-crossing.
- Use **concrete, literal** visual instructions — never metaphors ("living
  system", "constellation", "orbits", "heroic", "celebratory energy").
- Stay **provider-neutral**: no `--ar`, prompt weights, or camera/lens jargon.

## 8. Example Refactored Prompt (YouTube Thumbnail)

Concise, deterministic, provider-neutral (≈70 words; the four roles named, one
focal cluster, an explicit empty zone, one lighting and one depth cue):

```text
Flat vector illustration, slight isometric depth. One focal cluster of four
connected modules, offset right: an identity-and-access shield-and-key, a
branching event router with a small clock motif, stacked serverless function
tiles, and a compute cluster beside a monitoring gauge. Single bold arrow shows
left-to-right flow; connectors do not cross. Deep navy background with a faint
grid; amber and blue accents. Left third left empty for a headline. Soft
directional key light, gentle rim highlight. High contrast, strong silhouette,
generous negative space. No text. 16:9.
```

**Why this is production-ready:** one focal cluster; the four canonical roles are
each visually distinct and literal; a single non-crossing flow arrow; an explicit
empty headline zone; one lighting and one depth instruction; brand palette only;
no metaphors, no provider syntax, no rendered text.
